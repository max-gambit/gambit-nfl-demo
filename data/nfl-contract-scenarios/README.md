These eight dossiers support bounded contract scenarios for the Giants demo. `dossiers.json` is the canonical captured source bundle for this module; it does not replace `data/nfl-demo/current.json` or refresh the league roster. Roster association/status is the September 7 saved snapshot. Contract tables were inspected on September 8, 2026; exact times and content hashes are attached to each dossier.

The scenario subjects are Brian Burns, Andrew Thomas, Paulson Adebo, Jon Runyan, Darius Slayton, Courtland Sutton, Jakobi Meyers, and Christian Kirk. Selection establishes contract coverage, not football fit or trade availability. Kirk's saved roster category is `rsr`, not active. Slayton is a source conflict: the saved roster ledger describes an active Giants contract, while the inspected player page has no current contract and reports termination of the 2025 contract plus 2026/2027 dead-money charges. The module blocks calculations from that stale active ledger without mutating the roster.

Each dossier retains the original reviewed `source_data.contract_years`, fresh player-page component and transaction rows, explicit player-page void labels, trigger annotations, annual cash payout reporting, section-labeled source tables, unknown fields, URL, capture time, and SHA-256 of the inspected response. Existing source `cash_due` fields are not treated as verified unpaid compensation or total annual payouts. A converted bonus can make those measures differ. Even the source's annual cash-flow and cash-payout displays may use different conventions; they are retained separately and not reconciled by guesswork.

The module uses the executed NFL–NFLPA 2020 CBA, [Article 13 §6(b), printed pp. 109–110, and Article 26 §1, printed p. 171](https://nflpaweb.blob.core.windows.net/website/PDFs/CBA/March-15-2020-NFL-NFLPA-Collective-Bargaining-Agreement-Final-Executed-Copy.pdf). The former governs bonus proration and acceleration; the latter supplies salary floors. The official NFL description says the agreement runs through 2030. Scenario transactions are restricted to 2026–2029 so the special final-CBA-year acceleration treatment is not silently bypassed.

The runtime API is exported from `server/src/nfl_contracts/index.ts`:

- `getNflContractDossier(playerIdOrName)` and `getNflContractDossierCoverage()` return cloned source records and conflict/availability boundaries for ordinary player searches.
- `validateNflContractScenarioArgs(unknown)` performs strict structural validation and rejects unknown fields.
- `calculateNflContractScenario(args, optionalTestDossiers)` is pure and deterministic. Conflicting actions, source gaps, protection constraints, or duplicate aliases yield a blocked result with null aggregate values.
- `buildNflContractScenario(args)` returns a `FactualAnswer` plus serializable `scenario_args` and `scenario_result`. Tables, calculations, source refs, and metadata are server-owned. Persist both typed fields alongside the resulting brief.
- `calculateNflContractComparison(args)` / `buildNflContractComparison(args)` calculate hold, acquisition without funding, and the requested funded acquisition over the same selected players and years. They include cap/cash changes, reserve fit and controlling CBA provisions. The generated hold case never replaces the requested scenario in saved continuation state. Guarantee changes are not calculated by this comparison.
- `NFL_CONTRACT_SCENARIO_TOOL_SCHEMA` describes the economical model-call input; it supplies no numerical defaults.

All move `cap_before` values are from the same reported hold schedule, except illustrative incoming contracts whose acquiring-team baseline is zero. `cap_relief = cap_before - cap_after` preserves negative relief. A post-June departure derives its following-year tail from the difference between the same source's pre/post transaction dead-money columns. This is a conditional public-reporting model; payment status, guarantees, offsets, options, injury protection, termination pay, and incentives can change the executable answer. No release cash saving is fabricated. The user's budget is available capacity before the moves, not a team balance fetched by this engine. Cap and cash budgets use their respective net changes, then subtract the user's reserve. `fits` is conditional when the result is conditional; blocked or unknown values remain null.

For simple restructures, only a supplied conversion amount is modeled, over existing active years, at most five. No extension or new void years are invented. With no credited-season input the highest veteran salary floor is used conservatively. An optional unpaid-salary amount can constrain the calculation, but it does not establish contract consent or remaining weekly minimum compliance. Annual cash change is zero; bonus payment timing and guarantee implications stay explicit.

Actual acquisitions do not adopt seller cap numbers or seller savings as incoming obligations. Without complete assigned terms they are blocked and show original-club charges separately. A complete `user_supplied_illustrative` schedule can model new bonus, base/other compensation, incentive cap/cash amounts, guarantees, prior-team payments and obligations, and void years. Every dollar field, including zero, must be supplied; missing guarantees are not zero. The first void accelerates remaining new bonus under an explicit pre-June void assumption. The simple illustration excludes unlisted options, contingent vesting, deferred compensation and escalation; it is not an extension/offer solver or a minimum-salary legality determination.

Illustrative `guaranteed_salary` and `guaranteed_other_cash` are outstanding guarantees after prior-team payments, explicitly supplied by the user. They cannot exceed unpaid salary/other cash. This avoids guessing which prior payments satisfied guaranteed obligations. They exclude the newly specified signing bonus, which is separately fully guaranteed. Public dossier guarantee columns remain the original reported annual columns and are not recast as outstanding guarantees.

Call `validateNflScenarioInputProvenance(args, { current_question, prior_args? })` before executing model-proposed assumptions. It returns `{ ok, gaps: [{ path, code, message }] }`, binds each new amount to its specific player/year/field in the actual user text, and permits exactly unchanged values for the same player's previously executed inputs. Signing bonus, annual salary, outstanding guarantees, prior payments/obligations, conversion, budget and reserve are distinct fields. Bare years never supply currency. The recognized prose is intentionally bounded; unknown or ambiguous values return gaps rather than invented defaults. Explicit all-zero category clauses are required for unmentioned compensation, guarantees, incentives and prior payments/obligations. Multiple players' financial terms must be stated in separate sentences. New active/void year sets must be explicit.

The orchestrator supplies actual current user text and server-retained executed `prior_args`, never model-authored substitutes. For new illustrative terms, set `user_input` to the entire current question verbatim. On a partial follow-up retain the same player's original `user_input`; alternatively append a blank line and the entire new question. Rewriting or summarizing the literal source fails validation. Setting this source metadata outside the model is supported; each changed numerical field is still checked against the actual current question. Do not pass examples or suggestions as user-approved assumptions. Changing compensation requires recalculation from the changed full typed input, not an edited displayed total.

To repeat the bounded source capture: `python3 scripts/capture-nfl-contract-dossiers.py`. This is a local artifact refresh and makes public HTTP reads only. Review the changed source tables/conflicts before use. Broad roster/cap refresh is outside this capture.

Verification: from `server`, run `npx tsx --test tests/nfl_data/test_nfl_contract_scenarios.test.ts` and `npm run typecheck`. Test arithmetic uses hard-coded independent expectations for negative relief, timing, guarantee gaps, original-team tails, duplicate/incompatible moves, protected players, reserve/cash constraints, changed compensation, and explicit void acceleration. The complete illustrative fixture is a test input, not an actual offer or user decision.
